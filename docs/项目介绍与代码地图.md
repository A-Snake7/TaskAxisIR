# 项目介绍与代码地图

## 1. 项目目标

ProMamba 用同一个图像恢复框架处理去雨、去雾、去噪。`oracle` 模式需要任务标识；`blind_soft`、`blind_v2` 和 `blind_v3` 从退化图像预测条件。当前研究重点是 Blind-v3：利用整图与局部视图的退化信息进行路由，选择或混合恢复输出头。

主训练链路为：

```text
数据及训练/验证清单
  → AllInOneDataset + BalancedTaskBatchSampler
  → ProMamba / HierarchicalProMamba
  → 恢复损失 + 路由辅助损失
  → 优化器、AMP、EMA
  → 验证集评估、保存 latest.pth / best.pth
  → 独立测试集正式评测
```

这份说明介绍代码组织，不把某个模块的设计动机当作已验证的性能结论。

## 3. 模型组件

`net/promamba_v2.py` 虽然文件名带 v2，也实现了 Blind-v3。

| 类 | 作用 |
|---|---|
| `DegradationEncoder` | 从特征预测退化表示与任务分类 logits |
| `ReliabilityAwareRoutingFusion` | 温度校准全局和局部概率，再根据置信度、熵、分歧及特征学习融合权重 |
| `PromptAffine` | 根据条件向量进行特征仿射调制 |
| `PromptLocalFrequencyBlock`（PLFB） | 局部卷积分支与低/高频分解分支，使用条件门控融合 |
| `FourDirectionMambaBlock`（FDMB） | 水平/垂直正反方向 Mamba 扫描，与局部频率路径融合 |
| `HierarchicalProMamba` | 三尺度编码、瓶颈、解码与任务输出头 |

PLFB 的频率分解通过平均池化构造低频、通过残差构造高频，并非逐层FFT。局部条件修正形如 `c_gate = c_global + η·tanh(A(z_local))`，主要作用于门控条件。当前完整模型配置默认不让融合概率替换 PromptAffine 的整图条件。

## 4. 当前消融代码在哪里

相对主源码，`ablation_overrides/` 提供被冻结用于实验的扩展。主要开关和含义如下：

| 消融 | 关键参数 | 解释 |
|---|---|---|
| PLFB仅局部 | `--no_frequency_branch` | 关闭PLFB频率支路，保留局部建模 |
| FDMB卷积替代 | `--bottleneck_type conv` | 以5×5深度卷积、GroupNorm、SiLU和1×1卷积替代Mamba扫描路径 |
| 关闭局部条件修正 | `--local_condition_scale 0` | η=0，严格结构效果对照需要从零重训 |
| 路由方式 | `--v3_route_mode learned/global/local/equal` | 学习融合、仅全局、仅局部或等权融合 |
| 教师方式 | `--v3_teacher_mode stronger/global` | 比较一致性监督的教师选择策略 |
| 无一致性损失 | 两项一致性权重置零 | 取消路由及特征一致性约束 |

新增的 `utils/chapter6_inference.py` 区分逐块独立、图像级共享聚合、仅全局共享三种推理路由。三者固定同一模型、整图上下文和分块设置；该对照与重新训练“仅全局路由模型”的实验不是同一件事。

`experiment_tools/` 保存以下流程参考：

| 文件 | 来源与用途 |
|---|---|
| `routing_pair_evaluate.py` | 第一阶段路由聚合对照与召回率统计 |
| `priority_experiment_worker.py` | PLFB/FDMB/η=0串行实验、敏感性和效率测量 |
| `resume_training_queue.py` | 2026-09-20续训控制，备份后恢复FDMB并继续η=0 |

这些文件为只读参考副本，内含原始服务器路径，并依赖未备份的计划JSON、数据、检查点等。它们不是本地一键运行入口。

## 5. 数据、评测和测试工具

`scripts/` 保留数据构建与审计脚本，包括清洁数据根目录构建、数据泄漏检查、场景级训练/验证划分以及测试数据核验。只备份这些处理逻辑，没有备份任何实际数据或划分清单。

正式五条件评测为去雨、去雾、去噪σ=15/25/50；脚本记录文件顺序、检查点哈希、推理精度和每图指标。正式整图FP32结果与分块推理结果须分别标注，不能混用。Avg-5是五个条件的等权均值。

`tests/` 包含核心、Blind-v2、Blind-v3与盲推理测试；`scripts/*smoke*.py` 包含更接近集成流程的冒烟检查。本次备份只做文件完整性及Python语法检查，没有在Windows上运行GPU测试或训练。

## 6. 环境与阅读顺序

原项目说明记录 Python 3.8、PyTorch 2.0.1/CUDA 11.8，服务器使用 `airnet` Conda环境；依赖包括 `mamba-ssm` 和 `causal-conv1d`。实际实验硬件为 NVIDIA L40。`requirements.txt` 保留原样，正式评测代码还导入 `scikit-image`，原清单未列出该项，因此不能把它视为完整的环境锁文件。

建议阅读顺序：

1. 本地导读 → 原始README，了解任务与协议。
2. `net/promamba.py` → `net/promamba_v2.py`，理解模块与数据流。
3. `dataset.py` → `utils/losses.py` → `train.py`，理解训练。
4. `utils/inference.py` → `scripts/evaluate_aio3_promptir.py`，理解结果如何产生。
5. 对照 `ablation_overrides/` 和 `experiment_tools/`，理解当前实验设计。
